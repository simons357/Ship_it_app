## The product that matches what you just named

**One line:**

#### Problems it actually solves

| Pain in the OR | What Operator Assist does |
| --- | --- |
| Alarm / waveform overload | Mode-shaped glass: ready = quiet; emergency = stripped |
| Cognitive tunneling in crisis | Forces a short menu (A / B / C) instead of a wall of data |
| “What next?” under uncertainty | Decision tree over state → likely branches → ranked options with why |
| Junior / relief / handoff load | Same stack: state → options → chosen path logged |
| Index lag (companion, not replace) | Optional Vigilant-style *trajectory* cue feeds the menu earlier |

#### What it is **not**

- Not closed-loop drug delivery without a human  
- Not “diagnose / treat / FDA-cleared” until true  
- Not a dashboard novel  
- Not Millennium math on the glass  

#### A-grade MVP shape (exploratory but real)

1. **State card** — 5–7 plain lines: airway, hemodynamics, depth-class, surgical phase, trend (improving / drifting / tipping).  
2. **Load meter** — operator cognitive load proxy (alarm rate, conflicting trends, time-since-decision). Cross threshold → **emergency mode**.  
3. **Quantum Menu** — always ≤3–5 options. Each option: action, why, what to watch next, kill criteria.  
4. **Custom always allowed** — type exactly what you mean (same law as your other products).  
5. **You choose** — system never auto-fires clinical actions in v1.  

**Fresh angle:** most CDS dumps scores or 40-item checklists. Yours **sheds** information and sells **options under load** — aviation CRM + your trauma nights as the UX contract.

**Paper companion (A-grade):** perspective on decision augmentation / cognitive load — pairs with “When the Number Lags the Room,” not with Clay.
