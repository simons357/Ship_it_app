## 1. Fire fighting / wildfire support

**Framing (from existing plan pack):** California firefighting concentration and wildfire support are already in the TITAN-X materials (`CONSOLIDATED-SUMMARY.md`, investor PDF lane). This page restates that lane for the re-send.

| Role | Planning language |
| --- | --- |
| **Persistent overwatch** | Stay on station over a fire complex or high-risk corridor — thermal / smoke-plume / fire-behavior sensing without constant aircraft burn |
| **Communications / C2** | Incident-command and temporary comms packages so ground teams keep a lofted relay when terrain or smoke kills line-of-sight |
| **Spotting / decision support** | Wide-area observation for spot fires, evacuations, and resource allocation — feed incident commanders, not replace them |
| **Retardant / water modules** | Existing plan pack already lists **retardant or water delivery modules** as a firefighting configuration option — planning claim from the vault, not a demonstrated drop system in this pack |

**Do not say:** “we operate a certified aerial tanker fleet today.”  
**Do say:** “modular wildfire support — overwatch, comms, spotting; retardant/water as a module option already called out in the plan pack.”

Pre-positioning logic matches the parent summary: hours-scale regional response vs. surge-from-zero.

## 2. Science — atmospheric & astronomy platform

**Framing:** Use the same free-flight stratospheric hull as a **persistent science loft** in the aircraft–satellite band (planning altitude range in the parent PDF).

| Role | Planning language |
| --- | --- |
| **Atmospheric science** | Long-duration sensing above weather / below orbit — composition, radiation, electromagnetic, and environmental packages (instrument suite is modular / partner-supplied) |
| **Astronomy / observation** | Stable high-altitude platform for optical / IR / other instruments that benefit from less atmosphere than ground sites and more persistence / mass budget than many balloons or aircraft sorties |
| **Why TITAN-X** | ~20,000 lb modular payload + buoyancy/solar endurance → host instruments, power, and telemetry without framing this as a finished observatory product |

Civil and academic partners can own the instruments; Prime Field’s offer is the **persistent host + modular interfaces**. Keep OMEN (tethered spectral) off this page — different concept.

**Do not say:** “operational space telescope” or invent instrument performance numbers.  
**Do say:** “stratospheric science / astronomy platform option on the same modular hull.”

## 3. Harbor / port protect

**Framing:** Persistent coverage over a harbor, port complex, or approaches — **maritime domain awareness** plus the same **modular anti-drone bay** used for military interest ([`ANTI-DRONE-PAYLOAD.md`](ANTI-DRONE-PAYLOAD.md)).

| Role | Planning language |
| --- | --- |
| **Persistent stare** | Station-keeping over port approaches, anchorage, and critical waterfront infrastructure |
| **Maritime awareness** | Ship / small-craft / surface picture support (sensors modular; not a claimed finished MDA product) |
| **Anti-drone layer** | Raptor-class interceptor/effector and/or laser effector as drop-in modules for UAS threats to ships, terminals, and waterfront — outsource/integrate the effector |
| **Comms / observation** | Temporary relay and wide-area observation when port IT / towers are degraded |

Civil port security and dual-use / defense-adjacent harbor protection share the same module logic: swap ISR, C-UAS, or comms packages without a separate hull fleet.

**Do not say:** “fielded port C-UAS system” or invent CONOPS for a named terminal.  
**Do say:** “persistent harbor coverage + modular anti-drone payload options on TITAN-X.”
