# Outward Gate

**Name for the event:** before anything faces the world, it is analyzed.

Not a vibe. A step. Same family as emergency mode and the fast loop — except this one is about the **boundary** between private work and public surface.

You’ve felt this in the OR and in shipping work. You may not have seen it *named* as a product/process event before. Here it is:

> **Outward Gate** — a deliberate check that runs on every forward-facing object before it leaves. Sanitize, classify, then release (or hold).

---

## What gets checked

| Check | Question |
| --- | --- |
| **Secrets** | Passwords, keys, tokens, private emails that shouldn’t be public? |
| **IP / math engine** | Claims, recipes, enabling detail that belong under NDA? |
| **Offense / brand** | Would you put your name on this in a room? Intentional edge vs accidental mess? |
| **Confusion** | Two projects saying the same thing? Dead links? Draft notes that look official? |
| **Medical / legal claims** | Sound like promises you didn’t mean to make? |
| **Clone reality** | Public = anyone can copy. Are we okay with that for *this* object? |

If it fails the gate: **don’t send.** Fix, strip, or keep private.

---

## Modes of the gate

| Result | Meaning |
| --- | --- |
| **Release** | Fine for public / forward-facing |
| **Release-lite** | Titles and demos only; guts stay vaulted |
| **Hold** | Not ready — private repo, NDA, or not online yet |
| **Intentional edge** | Sharp on purpose; you chose that (rare; document why) |
